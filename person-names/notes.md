# 人名は「姓＋名」ではない

「人名は姓と名の2要素から成る」という前提は、それに当てはまらない人を締め出す。

---

## 1. 出発点：名前に関する誤謬

Patrick McKenzie「Falsehoods Programmers Believe About Names」（2010）は、プログラマーが名前について無自覚に置いている前提を40項目にわたって否定した。その一部を抜粋する。

- 人には正確に1つのフルネームがある（#1）
- 名前は決まった文字数に収まる（#6）
- 名前はASCIIで表せる（#9）
- 名前はUnicodeで表せる（#11）
- 名前には少なくとも1つ、家族で共有される部分がある（#18）
- 人には名前がある（#40）

本LTでは「姓＋名の2要素」という前提に絞り、それが実際に誰をどう締め出しているかを、規格・人口・実サービスの3方向から確認する。

---

## 2. 国際規格は2要素を前提にしていない

### ICAO Doc 9303（旅券。ISO/IEC 7501が参照）

- 名前は「姓／名」ではなく、**第一識別子／第二識別子**として定義されている。
- 名前を2つに分けられない場合は、**名前全体を第一識別子**とする。第二識別子は空でもよい。
- 目視で読む部分（VIZ）は各国の文字のままで、機械読取部分（MRZ）はラテン大文字のみ。MRZは意図的に情報を落とした**派生表現**である。
- MRZの名前は、規定の手順で切り詰める場合を除き切り詰めない。アポストロフィは削除し、ハイフンは区切り文字に置き換える。

### ISO/IEC 18013-5（モバイル運転免許証）

- `family_name` は「姓、名字、**または第一識別子**」と定義されている（二次情報による。ISO原文は未取得）。
- Unicode表記用の要素が別に用意されている。

**読み取れること**: 規格は「原本の名前」と「用途ごとの派生表現」を分けて扱い、2要素への分割を必須にしていない。入力フォームが規格から借りるべきなのは、MRZのA–Zや39文字といった**制約ではなく、この構造**である。

---

## 3. 世界の名前は2要素に収まらない

出典は英国政府作成・インターポール配布の命名慣習ガイド（2006）、W3C「Personal names around the world」、各種報道。

### 姓がない／大半が姓を持たない

| 国・地域 | 構造 |
|---|---|
| インドネシア | 多くの人に姓がない。1語だけの名前もある（スカルノ、スハルト）。旅券にも姓名の区別がない |
| ミャンマー | 姓の伝統がなく、名前全体が個人名。「U」のような敬称が名前と一体化する |
| タミル系（スリランカ・南インド） | 「父の名＋本人の名」。父の名は頭文字にされることが多い（A. Rasiah） |
| ソマリア | 「本人の名＋父の名＋祖父の名」。本人を特定するには3つすべてが必要 |
| アフガニスタン | 伝統的に姓がない |

### 姓に見えるが、実は父称

- **アイスランド**: 父の名＋-son／-dóttir。電話帳は名で並ぶ。
- **マレーシア**: Isa bin Osman のように、bin（〜の息子）で父の名をつなぐ。
- **アラブ圏**: 本人・父・祖父の名を連ねる。同じ人が複数の正当な形で名乗る。

### 日本にない構成要素がある

- **シンハラ系**: 家系名（gē名）＋名＋姓。家系名は頭文字にされたり省かれたりし、農村部では姓がないこともある。
- **シク教徒**: 名＋Singh／Kaur。姓は伝統的に使わない。

### 姓が2つ以上ある

- **スペイン語圏**: 父方と母方の2つの姓。
- **ブラジル**: 3〜4つの姓もある。並び順はスペイン語圏と逆。

### 制度も揺れている（インドネシア）

- 2022年の内務大臣令73号で、名前の登録基準は「最低2語・最大60字」になった。
- ただし当局者は、1語でも本人が強く望めば認めると説明している。
- 2022年以前に登録された1語の名前は今も有効。
- 運用の実態は**未検証**（2025年の報道では「1語は不受理」とされている）。

## 4. 人類の何割が「姓＋名」に収まるか（フェルミ推定）

直接のデータは見つからなかった。人口は国連の世界人口推計2024年版の概数を使っている（出典は未取得）。

| 定義 | 内容 | 推定 | 幅 |
|---|---|---|---|
| 広義 | 世襲の姓があり、姓欄と名欄に分けられる | **約80%（約65億人）** | 75〜85% |
| 狭義 | 日本型（姓1語＋名1語。ミドルネーム・複数の姓・父称なし） | **約45%（約36億人）** | 35〜55% |

- 結果を最も大きく左右するのはインド（±2.7ポイント）とアフリカ（±2ポイント）。
- **日本型（狭義）の約4割は中国の人口**であり、日本型が多数派に見えるのは中国の人口の大きさによる。
- **広義で漏れる約2割（15〜17億人）は、インド一国の人口に匹敵する**。

「姓を必須にする」という設計は、外れ値ではなく十数億人を相手にしている。

## 5. 実サービスの調査

調査方法: Playwrightでダミー値を入力し、検証メッセージを観察した。アカウントの作成・確定には一度も到達させていない。

### 結果一覧

| サービス | 姓または名が空 | 文字の範囲 | 長さの上限 | 読み（カナ） |
|---|---|---|---|---|
| Google | **姓は任意** | ほぼUnicode全般 | 名は50文字 | なし |
| Apple | 両方必須 | ほぼUnicode全般 | 名は32文字 | なし |
| Facebook | 両方必須（1語の名前は別途申請） | 独自の推定ルール | あり | なし |
| 楽天（旧フォーム） | 両方必須 | **JIS X 0208相当** | 各欄85文字 | 全角カタカナで必須 |
| ゆうちょダイレクト | **カナ1欄のみ** | カタカナ中心 | 30文字 | 唯一の氏名欄 |

### 楽天（旧フォーム）

1語の名前は、姓だけ・名だけでは拒否され、**同じ語を両方に入れると通る**。

拒否された入力（「登録できない文字があります」）:
- ダイアクリティカルマーク付き文字（ü、ë）
- 異体字（髙、𠮷）、互換漢字（﨑）
- ハングル、簡体字、アラビア文字、ミャンマー文字、シンハラ文字
- 絵文字、丸数字

通った入力:
- キリル文字（Иванов）
- 数字
- `O'Brien-Smith`

**エラーを出さずに書き換えられる入力**:
- `山<田` → `山`（`<` 以降が消える）
- `デ ラ トーレ` → `デラトーレ`（スペースが消える）
- ひらがな・半角カナ → 全角カタカナ

フリガナ欄では中黒「・」が拒否されるため、「メアリー・アン」のような外国人名の区切りは表現できない。

通る文字と拒否される文字の境界はJIS X 0208とよく一致する。ページ自体はUTF-8なので、制約はバックエンド側にあると**推測**する。

### ゆうちょダイレクト（新規利用申込み）

- 氏名欄は「氏名（カナ）」の**1欄だけ**で、姓名を分割しない。そのため1語の名前もそのまま入力できる。
- 拒否された入力: ひらがな、半角カナ、漢字、**中黒「・」**。
- 通った入力: ラテン文字、ハイフン、ピリオド、括弧、スペース。
- 規定には、カナ氏名が一致しないと申し込めない旨の条項がある。カナ氏名が照合キーになっている。
- 試行を重ねたところ「一定回数誤りが続きましたのでログアウトしました」と表示されたため、検証を打ち切った。

### Google

- 名のみの入力、1文字の名前、数字、`Zoë`、`𠮷`、ハングル、アラビア文字、ミャンマー文字、シンハラ文字、文字種の混在はすべて通過。
- 拒否されたもの: `<`、絵文字、URL風の文字列、空白のみ、51文字以上。

### Facebook

ヘルプでは、1語の名前は**フォームの外で申請する**よう案内している。「同じ名前を姓と名の両方の欄に入れて送信」という手順。

| 入力 | 結果 |
|---|---|
| 数字 | 拒否 |
| `mcDONALD`（大文字小文字の混在） | 拒否（大文字が多すぎる） |
| `Dr. Smith` | 拒否（ピリオドが多すぎる） |
| `Zoë` | **拒否**（「タイトルまたはシンボル」扱い） |
| `Müller`、`José`、`Nguyễn` | 通過 |
| `Pablo Diego Jose Francisco de Paula Juan` | 拒否（「有名人と同じ名前」） |
| シンハラ文字 | 拒否 |

判定基準に一貫性がない。サーバー側の最終審査は**未検証**。

### Apple

- 姓と名は両方必須。ミャンマー名を名の欄だけに入れると拒否された。
- `<` と絵文字は拒否。それ以外の文字はほぼ通過。
- 名は**32文字**まで（調査した中で最も厳しい）。
- CAPTCHAがあるため送信はしておらず、サーバー側の判定は**未検証**。

### 悪い例：三重県 e-TUMO apply（電子申請）

システムの制約を回避するため、県は利用者に次のように案内している。

- 読みをカナで表せない場合は、「氏」に"シ"、「名」に"メイ"と入力する。
- 姓が後ろに来る文化の名前は、名を「氏」の欄に、姓を「名」の欄に入れる。
  - 例: `John Fitzgerald Kennedy` → 「氏」John、「名」Fitzgerald Kennedy

システムの制約を利用者の運用で吸収した結果、**保存されるデータの意味が壊れている**。

## 6. 観察から言えること

1. **姓を必須にするかどうかは、照合キーの設計で決まっている。**
   - 表示用の名前を扱うGoogleは姓を任意にしている。
   - 身元照合を重視するFacebook・楽天・Appleは、姓と名を両方必須にしている。
   - 1語の名前は「同じ語を両方の欄に入れる」という**裏技**で扱われている。
2. **国産サービスは文字セットが狭い。** 楽天はJIS X 0208相当、ゆうちょはカタカナ中心。ベトナム語・韓国語・多くのヨーロッパ系の名前は、本来の綴りでは登録できない。
3. **黙った書き換えが最も危険。** 本人が知らないうちに原本が変わり、後で照合に失敗する原因になる。
4. **推定による判定は、正当な名前を誤って拒否する。** Facebookの `Zoë` が例。

## 7. 手本になる候補

### 設計の基準

- **GOV.UK Design System（英国政府）**
  - 1欄の「Full name」を例として示している。
  - 数字や記号を含め、利用者が必要とする文字をすべて受け付けるよう求めている。
  - 分割すると、名前がその形式に収まらない危険が増すと明記している。
- **USWDS（米国政府）**
  - 各欄128文字まで受け付ける。
  - **どの欄も必須にしない**。インドネシアやアイスランドには1語の名前の人がいることを理由に挙げている。
  - 大文字小文字を正規化しない。
  - 「旧姓」ではなく「以前の名前」を尋ねる。

### 実サービス

- **表示用**
  - **GitHub**: 名前はName欄1つ。プロフィールの名前は実名と一致させる必要がないと明記している。
  - **Slack**: フルネーム（必須）と表示名（任意）の2層。ただし英語の予約語に `ja` と `ms` が含まれ、Jaという名前の人は使えない。
- **本人確認（KYC）**
  - **Wise**: 法的な氏名と呼んでほしい名前を分けている。姓名の欄がないインドネシアやマレーシアの身分証明書にも対応する。ただし**2語以上が条件**なので、1語の名前は通らない。

**単独で満点のサービスは見つからなかった。** 最も理想に近いのは次の組み合わせ。

- 骨格はUSWDS（必須欄なし、1欄128文字、正規化しない）
- Wiseの「法的な氏名」と「呼び名」の2層構造
- Wiseの「2語以上」条件は外す
- 本人確認をしない用途なら、GitHubのように実名との一致を求めない

## 8. 規定案：名前は入力フォームでどう扱うべきか

1. **用途を先に決める**（照合／表示／呼びかけ／並べ替え／外部連携）。必要なものだけを集める。
2. **正となる欄は「氏名（全体）」1つ**にし、入力されたまま保存する。
3. **分割が必要なら**、ICAOの第一識別子／第二識別子の考え方で分け、**第二識別子は空でもよい**ことにする。
4. **字種はUnicodeを全面的に受け付ける。** 拒否するのは制御文字と不可視文字程度にする。
5. **長さに小さな上限を設けない。** 上限は乱用対策として十分に大きく取る。
6. **原文字・ラテン文字・読みは別の欄にし、本人に入力してもらう。** 自動でローマ字化した値を正としない。
7. **敬称や称号は別の任意欄にする。** 名前から勝手に削らない。
8. **照合用の正規化は派生キーとして作り、原本は書き換えない。** NFCでもCJK互換漢字は別の字に置き換わる。
9. **名前を一意キーや同一人物の判定に使わない。**
10. **変更履歴と複数の名前を持てるようにする。** ラベルは「旧姓」ではなく「以前の氏名」にする。
11. **「お呼びする名前」の欄を別に設ける。**
12. **並べ替えのキーは本人の入力か、ロケールの規則に従う。**
13. **本名の欄に不適切語フィルタをかけない。** 1文字の名前も拒否しない。
14. **外部連携用の値は、明示的な規則で派生させて別に保存する。** 本人に確認・編集してもらう。
15. **Unicodeで表せない字への逃げ道として、補足欄を用意する。**

---

## 9. まとめ

- 「姓＋名」に収まらない人は、**例外ではなく十数億人**いる。
- 国際規格すら2要素を前提にしておらず、「原本」と「派生表現」を分けて扱っている。
- 実サービスの多くは2要素を前提にしたまま、1語の名前を**裏技や人手の手続き**で吸収している。
- 対策は難しくない。**分割しない、必須にしない、書き換えない、文字を絞らない。**
